# 智序工作台（Zhixu Workbench）

个性化网站导航 + 多模型 AI 助手。**纯本地运行**，数据保存在你自己的浏览器里，AI 采用 **BYOK（自带 API Key）** 模式——你选择服务商、自己承担调用费用，本应用不提供统一的 AI 服务、内购或额度代付。

---

## 快速开始（30 秒上手）

> **在线体验（免安装）**：
> 国内网络建议用 [CloudStudio 演示站](https://ba090cdcaa6746b3a98dd5983ff8c2d6.app.workbuddy.host)；
> 长期固定链接为 [GitHub Pages](https://qiruixu.github.io/zhixu-workbench/)（`github.io` 在部分国内网络下可能打不开，属正常现象）。

本项目是**本地运行源码**，不需要全局安装、也没有安装包——把代码拉到本地、装依赖、起服务即可。

```bash
# 1) 拉取代码
git clone https://github.com/qiruixu/zhixu-workbench.git
cd zhixu-workbench

# 2) 安装依赖（需 Node.js ≥ 20，推荐 22）
npm install

# 3) 启动（前端 + 本地 AI 代理后端一起跑）
npm run dev
```

打开终端提示的地址，通常是 **http://localhost:5173**（本地后端代理在 `http://127.0.0.1:8787`）。
不配置任何 AI Key 也能用导航 / 课表 / 日程 / 天气；想用 AI 助手，到「AI 配置」页填入你自己的 Key 即可（详见 §5）。

> 想部署成纯静态站点（无需后端）？见 §16 直连模式。想生成不含密钥的安全分享包？见 §15。

## 1. 功能一览

### 新手引导
- 首次打开自动弹出**分步引导（共 7 步）**，用「聚光灯」高亮对应界面区域（找不到目标元素时自动退化为居中卡片）
- **重点覆盖「课表导入」与「AI 配置」**这两个新用户最容易卡住的模块，并会跨页面带你走一遍
- 可随时跳过；看完后可从**左侧栏底部**或**设置页**的「新手指引」重新打开

### 网站导航工作台（首页）
- 添加 / 编辑 / 删除网站；设置名称、网址、图标、分类、备注
- 创建 / 编辑 / 删除自定义分类（含配色）
- **拖拽排序**（支持同分类内排序、跨分类拖动直接归类）
- 收藏、置顶、搜索（名称 / 网址 / 备注）、分类筛选、快捷筛选
- 浅色 / 深色 / 跟随系统主题
- 首页布局自定义：显示或隐藏问候区、统计、搜索、快捷筛选、分组；调整卡片大小与列数
- 配置自动保存，刷新或重启后仍在
- 导航配置导入 / 导出（含**导入预览 + 结构校验**，默认合并去重，不静默覆盖）
- 内置示例网站（可自由修改或删除）
- 图标加载失败时自动退回首字头像，不会出现裂图
- 点击卡片在新标签页打开（默认不使用 iframe，避免被第三方站点拒绝）

### 多模型 AI 助手
- **四步极简配置**：选服务商 → 填 API Key → 选模型 → 测试连接
- 内置常见服务商预设（自动填充 API 地址与推荐模型）：DeepSeek、**NVIDIA NIM（已实测验证）**、硅基流动、OpenAI、智谱 GLM、月之暗面 Kimi、阿里云百炼、OpenRouter、火山引擎、Ollama（本地），以及**自定义 API**
- 预设集中管理（`src/lib/providers.ts`），且界面允许随时编辑；模型列表可**从服务端动态刷新**，避免预设过期
- 多配置管理：新增 / 编辑 / 删除 / 复制 / 切换当前配置 / 测试连接 / 显示当前服务商与模型
- 明确的错误分类提示（Key 错误、模型不存在、余额不足、限流、地址错误、超时、网络失败等）
- 聊天：流式输出、Markdown 渲染、代码块一键复制、多会话、新建 / 切换 / 删除 / 清空、停止生成、复制回答、失败重试
- 未配置 AI 时给出清晰引导，**绝不伪造 AI 回复**

### AI 与导航联动
- 「整理我的导航」：AI 分析当前导航 → 生成分类建议 / 合并重复分类 / 补全未分类 / 重命名
- **建议 → 预览 → 用户确认 → 执行**，未确认前数据零改动
- 受控机制：AI 仅输出结构化操作建议（JSON），不执行任何代码、不访问本地文件

### 首页面板带：今日课程 + 日程备忘 + 天气

位于首页问候区下方、站点网格上方，三块面板并排（窄屏自动堆叠），可在「布局」里整块隐藏或分别隐藏。

**课程表**
- **把教务系统导出的课表文件直接拖到面板上即可导入/更新**（也支持点击选择文件）
- 自动解析：星期、大节、节次、课程名、教室、任课教师、周次、单双周、附加说明（如「(匹克球)」）
- 表尾的「备注：」行（课程设计等）会作为「其他安排」一并解析
- **按天切换**：`‹ 前/后一天 ›`，可直接看明天、后天的课；点中间日期或「回到今天」快速回到今天
- **按周切换**：右上角 `‹ 第 N 周 ›` 可整周前后跳，周次数字跟着浏览的日期自动变化
- **导入后自动定位当前周次**：系统会依据课表里的学年学期信息（如「2026-2027学年 第1学期」）或常见开学周，自动推算「今天是第几周」，**无需手动设置**；日历课表（.ics）按课程日期精确反推。界面上会如实标注周次来源，推算不准时可一键校准
- **周次自定义且会自己更新**：设定「某天是第几周」后，之后每过一个自然周自动 +1，不用每周手动改（也支持填「开学第一周周一」自动推算）
- **点日历联动**：点「日程备忘」里任意日期，课表立刻跳到那天的课；日历上有课的日期右上角有小圆点
- **多格式导入**：`.xls` / `.xlsx` / `.csv` / `.tsv` / `.rtf`（含很多教务导出的 `.doc`）/ `.docx` / `.pdf` / `.ics`（日历课表）；解析失败会给出明确原因，且**不会覆盖**已导入的课表
- 兼容多种导出布局：①「大节 × 星期」网格；②星期表头跨列合并、单元格自带星期（如 `周一 3-4节 1-18周`）；③单元格里紧凑排一行（`名称 课程号(1~15周) (1-2节) 地点  教师`，一格还能挤多门课）
- 周次支持 `1-7,10-11,14-16`、`1-18周`、`1~15,17周`、`1-7周(单)` 等写法，单双周会正确过滤

**按格式说明**

| 格式 | 典型来源 | 说明 |
|---|---|---|
| `.xls` / `.xlsx` / `.csv` / `.tsv` | 教务系统导出 | 最可靠，优先用 |
| `.rtf`（不少 `.doc` 其实是 RTF） | 教务系统导出 | 支持内嵌图片、竖向合并单元格 |
| `.docx` | Word 课表 | 支持表格合并、单元格紧凑排课 |
| `.ics`（iCalendar） | WakeUpSchedule 等课表 App | **按日期自动推算周次与学期起始**，无需手填开学日 |
| `.pdf` | 打印/另存的课表 | 实验性，见下 |

> **`.ics` 日历课表**：这类课表给的是**绝对日期**（每周重复 + 结束日），因此能自动算出「学期第一周的周一」并据此推算周次，也支持 `EXDATE` 排除调课。
> 导入后会按日期对齐周次锚点，隔周/单双周的课（如 `第2,4,6,8,10,12,14,16周`）在对应周才会出现。

> PDF 属于**实验性解析**（自研解析器，把表格还原成网格）：能被表格折行拆开的长课程名、以及源文件里重复的单元格可能提取不全。
> 若同一份课表还有 `.xls / .xlsx / .csv` 导出，**请优先用表格文件**。PDF 解析成功后界面会带一条同样的提醒。

**日程备忘**
- 月历视图，今天高亮；有安排的日期打点（未完成用实心点），有课的日期右上角有标记
- 点任意日期即可为该日添加/勾选/删除待办；Enter 快速保存；点日期同时会联动上面的课表
- 与课表互不影响，数据同样只存本机

**天气**
- 点「使用我的位置」用浏览器定位，或直接搜索城市（两者都支持，随时可切换）
- 显示当前温度/天气/体感/湿度/风速、未来 6 小时、未来 3 天（含降水概率）
- 定位只需授权一次，之后自动记住；也可一键「清除定位」
- 天气数据由本机后端转发；**后端没启动时会明确提示**「本地服务没有返回有效数据，通常是后端未启动」，而不是抛一句看不懂的解析错误

> 说明：课表文件本身**不含**上课时间，因此界面只展示「第 X 节 / 第 X 大节」，不虚构时间。
>
> **隐私提示**：使用天气功能时，坐标会发送给第三方公开数据源（Open-Meteo 与 BigDataCloud），
> 请求由本机后端转发。若不想暴露位置，可在「布局」里隐藏天气面板，或只手动选城市、不使用定位。

### AI 能读到你的课表 / 日程 / 位置

聊天页顶部有一个「我的日程」开关（默认开）。开启后，每次对话都会把下列内容作为**系统上下文**一并发送给模型：

- **当前时间**（含本学期第几周）
- **我的课表**：今天/明天/后天要上的课（节次、教室、教师、周次）＋表尾的其它安排
- **我的日程备忘**：未来两周的待办及完成状态
- **我的位置与天气**：所在城市与当前天气实况

因此可以直接问「根据我的课表，帮我安排明天下午的学习计划」，模型是真能看到你的安排的。
开关一旦关闭，模型就完全不知道这些信息——不会假装知道。

> 上下文中明确写了「缺少的信息请直接说明不知道，不要编造」，避免模型凭空推测你的位置或课表。
> 这些内容只在你主动发消息时、经本机后端转发给你自己配置的服务商，不会另存他处。

### 聊天内切换 API 与模型

聊天页标题下方是一个可点击的服务商/模型胶囊，点开后可以：

- 在**多份 API 配置之间切换**（列出每份配置的服务商与当前模型）
- 切换**当前配置下的模型**（从已知模型列表选，或手动输入任意模型名）
- 一键「刷新列表」从服务端重新拉取该服务商的模型

切换会**写回配置本身**并立即对后续对话生效，不是只改显示；新对话会记录当时使用的模型。

## 3. 安装与启动

```bash
# 1) 安装依赖
npm install

# 2) 启动（前端 + 本地 AI 代理后端 一起启动）
npm run dev
```

打开终端提示的地址，通常是 **http://localhost:5173**。

`npm run dev` 会并行启动两个进程：
- 前端（Vite）：`http://localhost:5173`
- 本地 AI 代理（Node/Express）：`http://127.0.0.1:8787`（前端通过 `/api` 代理自动访问）

### 其它命令

| 命令 | 说明 |
| --- | --- |
| `npm run dev` | 开发模式（前端 + 后端） |
| `npm run dev:web` | 仅启动前端 |
| `npm run dev:api` | 仅启动本地 AI 代理 |
| `npm run build` | 构建前端到 `dist/` |
| `npm start` | 生产模式：单进程启动，同时托管前端页面与 AI 代理（默认 8787） |
| `npm run typecheck` | TypeScript 类型检查 |

> 生产模式：先 `npm run build`，再 `npm start`，然后访问 `http://127.0.0.1:8787`。
> 端口可用环境变量调整：`API_PORT=9000 npm start`。
> 产物目录默认 `dist/`；如需托管其它目录：`DIST_DIR=dist-app npm start`。

## 5. 如何配置 AI

进入左侧 **AI 配置** 页面 → **添加配置**，按四步走：

1. **选择服务商**：从卡片中选一个（如 DeepSeek）。
2. **填写 API Key**：粘贴你在服务商控制台申请的 Key。
   - 默认开启「持久保存」→ 存在本机浏览器；关闭则仅本次会话内存保存，刷新失效。
3. **选择模型**：下拉选择，或点「从服务端刷新模型列表」动态拉取，也可手动输入。
4. **测试连接**：点击后会用「模型列表接口 / 最小对话请求」验证。
   - 成功：可到「AI 助手」开始对话。
   - 失败：会给出明确原因（Key 无效 / 模型不存在 / 余额不足 / 地址错误 / 超时 / 网络失败等）。

首次添加后会自动设为「当前配置」，侧边栏底部会显示当前服务商与模型。

> **关于预设的可靠性**：各服务商的接口地址与模型名会变化（例如 DeepSeek 已把 `deepseek-chat` 更名为 `deepseek-flash` / `deepseek-v4-pro`）。
> 因此预设只作**自动填充**之用，界面上所有字段都可编辑，并建议用「测试连接 / 刷新模型列表」确认真实可用性。未在本机实测通过的服务商一律标注为 **「待验证」**（目前 **NVIDIA NIM** 已完成真实联调，标记为「已验证」）。

### 5.1 免配置启动：本地引导配置（可选）

若希望**任何浏览器首次打开就已经配好 AI**，不必每次手动录入，可把配置放到本机文件里：

1. 新建 `zhixu-workbench/.local/ai-config.json`：

```json
{
  "activeConfigName": "NVIDIA NIM",
  "configs": [
    {
      "name": "NVIDIA NIM",
      "providerId": "nvidia",
      "baseUrl": "https://integrate.api.nvidia.com/v1",
      "apiKey": "你的 API Key",
      "model": "deepseek-ai/deepseek-v4.1-flash",
      "persistKey": true
    }
  ]
}
```

2. 重启 `npm run dev`（或 `npm start`）。应用启动时会自动拉取并写入，侧栏底部立即显示当前模型。

行为与边界：

- 由本机后端 `GET /api/bootstrap` 下发，**服务只监听 127.0.0.1**；
- **只有当本地库中一条 AI 配置都没有时才写入**，绝不覆盖你手动添加的配置；
- 用文件指纹记录已应用状态，你**手动删除后不会被反复恢复**（改了文件内容才会再次应用）；
- 自动写入的配置会显示「由本地配置自动写入」徽标，便于识别来源；
- `providerId` 可省略（缺省按 `custom` 处理），也可只填 `baseUrl` + `apiKey` + `model`。

> ⚠️ **安全提示**：该文件包含**明文密钥**。它已在 `.gitignore` 中排除、不随任何导出、也不会被上传；但仍属本机明文存储，请勿放在共享目录或公共电脑上。若更在意安全性，请不要使用此功能，改为在页面内手动录入并关闭「持久保存」。

## 7. 如何使用自定义 API

在服务商卡片中选择 **自定义 API**，然后：

- **API Base URL**：填兼容 OpenAI 协议的服务地址（通常以 `/v1` 结尾），如 `https://your-host/v1`
- **API Key**：对应密钥
- **模型名称**：手动填写该服务使用的模型标识
- 高级设置里可调整：对话路径（默认 `/chat/completions`）、模型列表路径、鉴权方式（Bearer / x-api-key / 自定义头 / 无需鉴权）、`temperature` / `max_tokens` / `top_p`、额外请求头（JSON）

若某服务商协议与 OpenAI 不完全一致，可通过上述「路径 + 鉴权方式 + 额外请求头」进行适配。

## 8. 如何备份和恢复数据

进入 **设置 → 数据管理与备份**：

- **导出导航配置**：得到 `zhixu-nav-YYYY-MM-DD.json`（仅含分类与网站）
- **导入导航配置**：选择 JSON 文件 → 自动**校验结构** → 弹出**导入预览** → 选择模式：
  - **合并导入（推荐）**：按网址去重后追加，不覆盖已有数据
  - **覆盖导入**：清空现有导航后导入（会二次确认）
- **导出聊天记录**：得到 `zhixu-chat-YYYY-MM-DD.json`
- **清除全部本地数据**：危险操作，需连续两次确认

> 清除浏览器数据会导致本地数据丢失，请定期导出备份。导出的两类文件均**不包含任何 API Key**。

## 9. API Key 如何保存及安全限制

| 项目 | 说明 |
| --- | --- |
| 保存位置 | 本机浏览器 **IndexedDB**（开启「持久保存」时）；或仅会话内存（关闭时） |
| 传输路径 | 浏览器 → **本机 Node 代理（127.0.0.1）** → 你配置的服务商地址。不经过任何其它服务器 |
| 日志 | 后端对请求做**脱敏**，不打印 API Key 与请求头 |
| 导出 | 导航与聊天导出文件中**不含** Key |
| 删除 | 「AI 配置」页可删除单份配置或一键清除全部密钥 |
| 本地后端约束 | 仅监听 `127.0.0.1`；CORS 仅放行 `localhost` / `127.0.0.1` 来源；仅允许 http/https |

**⚠️ 必须理解的风险**

- 任何存储在本机的方式（包括 IndexedDB）**都无法保证绝对安全**——同机上的其它程序理论上可能读取到本地存储数据。
- 因此请**不要在公共或共享电脑上保存密钥**。若仅在临时设备上使用，请关闭「持久保存」，让密钥只存在于本次会话内存中，用完关闭页面即消失。
- 本应用为本地个人工具，未实现操作系统级凭据存储（如 Windows Credential Manager / macOS Keychain）。这属于**已知限制**，后续可扩展。

## 11. 已知问题 / 限制

- **没有内置任何 AI 服务**：必须自备 API Key 才能对话；无 Key 时聊天页只显示引导，不会伪造回复。
- **服务商预设可能过期**：模型名称与地址由各厂商决定，随时可能变化。请以「测试连接 / 刷新模型列表」的结果为准；未实测的服务商标注为「待验证」，而非谎称兼容（目前 **NVIDIA NIM** 已完成真实联调，标记为「已验证」）。
- **密钥未接入操作系统凭据存储**：页面内录入时仅存于 IndexedDB；若启用「本地引导配置」，则另有一份**明文**存于 `.local/ai-config.json`（已 gitignore，仅本机 127.0.0.1 下发）。见上文安全说明。
- **浏览器图标获取**：默认取站点自身的 `/favicon.ico`。部分站点无该文件或做了防盗链，此时会退回首字头像（属预期行为，不是故障）。
- **AI 整理导航的准确度**：AI 看不到网站的**真实内容**，只能依据名称与域名推断；因此它**只提建议**，最终是否应用由你决定。
- **火山引擎（豆包）**：模型名通常需填控制台创建的「推理接入点 ID」，请按控制台实际填写。
- 未实现多 Agent 编排、语音、图片输入等高级能力（第一版范围之外）。
- **PDF 课表属实验性解析**：能被表格折行拆开的长课程名、以及源文件里本身就重复的单元格，可能提取不全或产生少量冗余条目（界面会带同样的提醒）。有 `.xls / .xlsx / .csv` 时请优先用表格文件。
- **旧版 Word 二进制 `.doc` 不支持**：这类文件不是 RTF、也不是表格，无法可靠取出表格结构；会明确提示「请在 Word / WPS 里另存为 .xlsx 或 .rtf 后再导入」。
- **课表不含上课时间**：教务导出的文件里通常没有每节课的起止时间，因此界面只显示「第 X 节 / 第 X 大节」，不虚构时间。

### 测试中发现并修复的真实缺陷

1. **代理把每个请求立刻中止**：原实现监听 `req` 的 `close` 事件判断客户端断连，但该事件在请求体读取完成后就会触发，导致上游请求刚发出就被 `abort`。已改为监听 `res` 的 `close` 并判断 `res.writableEnded`。
2. **服务商忽略 `stream` 时拿到空内容**：原实现只在「无响应体」时按非流式解析，若服务商返回 JSON 但带 body，会被当成 SSE 解析从而得到空字符串。已改为按 `content-type` 判断，并增加一次性 SSE 兜底解析。
3. **重试会重复提问**：重试时先删除最后一条用户消息再重发，避免对话中出现重复的用户消息。
4. **清除 AI 配置后侧栏状态不同步**：设置页清除配置时未同步「当前配置」状态，已修复。
5. **保存后丢失测试结果**：编辑器内「测试连接」成功，但保存时未把结果写入配置，导致卡片回到「待验证」。已在保存时一并持久化 `lastTestResult`。
6. **浏览器里读 CSV 中文乱码（课表解析）**：`XLSX.read(ArrayBuffer, {type:'array'})` 在浏览器中对文本类文件会按 Latin-1 解码，`星期一` 变成 `ææä¸`，导致表头识别失败（Node 下不复现，容易漏测）。已改为文本类文件先按 UTF-8 解码再用 `type:'string'` 解析，并在首选方式失败时自动尝试另一种，顺带兼容「HTML 伪装成 .xls」的导出。
7. **合并单元格导致备注重复**：备注行是横向合并单元格，展开合并时把同一段文字复制到 7 列，被重复计入。已改为按内容去重并全局清理前缀。
8. **旧版设置导致新模块永不显示（天气看不到了）**：`getSettings()` 原先是浅合并，旧版本存下的设置里没有后来新增的开关字段（`showWeather`），读出来是 `undefined` → 被当作「隐藏」。已改为对 `layout` 深合并——否则以后每次新增首页模块都会重现这个问题。
9. **后端未启动时天气报错看不懂**：天气接口由本机后端转发，后端没起来时 Vite 返回 HTML，`res.json()` 抛出 `Unexpected token '<'`。已统一转成「本地服务没有返回有效数据，通常是后端未启动」。
10. **「周次」完全识别不出来（课表解析）**：`([周])` 这种写法里「周」在括号内、数字在括号前（`1-7,10-11,14-16([周])[01-02-03节]`），原来按「数字紧跟周」去匹配，结果一门课的周次都拿不到，界面上全变成「周次未识别」。已单独处理这种写法；同时补上单双周 `1-7周(单)` 的过滤。
11. **RTF 里的二进制图片让解析器整个失效**：不少教务导出的 `.doc` 其实是 RTF，里面用 `\bin N` 内嵌 PNG。按花括号配对剔除图片时，二进制里的 `{`/`}` 会让括号计数失衡，导致表头之后的内容全被丢掉（现象是「找不到星期表头」）。已改为遇到 `\bin N` 按长度跳过。
12. **PDF 流多一个字节就解压失败**：`DecompressionStream` 是严格实现，PDF 数据流末尾多一个换行就会报 `Trailing junk found after the end of the compressed stream`。已改为优先按 `/Length` 精确切片、否则去掉尾部换行。
13. **`/Font` 误命中 `/FontBBox`、`/ToUnicode` 被截断成 `10`**：字典取值既没有校验键名完整匹配，也会在空格处截断间接引用 `10 0 R`，导致 PDF 的 ToUnicode 映射表拿不到、中文全丢。两个问题都已修复（键名加边界校验、间接引用读到分隔符为止）。
14. **逐字输出的 PDF 拼不出「星期一」**：有生成器把每个字单独放一次，导致表头识别失败。已按「相邻步距上限」合并同一行的文字片段（用行内步距与字号上限共同判定，避免把相邻两列粘在一起）。
15. **ICS 周次多算一次（日历课表）**：WakeUpSchedule 这类导出器把 `RRULE` 的 `UNTIL` 写成「最后一次上课当天的 00:00」，若只按「周跨度」推算会多排出一次课。已改为按**实际发生时刻**与 `UNTIL` 比较；因此「每 3 周一次的大学化学」精确到 `第6,9,12,15周` 而不是 `第6-7,9-10…周`。
16. **DOCX 里一格挤多门课被当成一门**：紧凑单元格（`名称 课程号(1~15周) (1-2节) 地点  教师`）连着排多门课时，原来整格只出一门。已按「`(周次)` 起点」切段，并让无名称的后续段继承上一门课的名称/编号（它们是同一门课的不同周次或不同教室）。
17. **DOCX 教师残留工号、课程名粘连**：教师提取用工号正则替换时漏了 `g` 标志，多教师（`刘增惠/赵金英`）只剥掉第一个工号；周次区间写法 `1~15,17周` 里的逗号让切段正则失配，导致下一门课的名字被当成上一门的尾巴。
18. **PDF 详情层污染课表**：PDF 信息层会把「教学班组成 / 学分 / 学时」整段塞进单元格，而且同一段文字常画两遍（双图层重叠）。原来这些被当成备注收进「其他安排」、或变成课程名。已在详情字段处切断，并按 `/场地:` `/教师:` 显式标记提取，不再靠位置猜。
19. **`★`/`○` 标记被拼回课程名**：名称尾部的 `★`（必修）被摘下来当附注后，又因为「看起来像折行续接」被拼回名称尾部（`工程制图与CAD` → `工程制图与CAD★`）。已把标记补回放到续接判定之后，并让「以标记结尾的中文名」（如 `基础英语Ⅰ★`）被判为**另一门课**而不是续接。
20. **PDF 末尾「课程索引行」被当成课表**：PDF 最后几行常把本页课程名列成清单（没有节次/周次），原来会被逐条当成一门课。已改为多行名称堆叠且无节次锚点时不认。
21. **合并单元格展开后产生假课程**：星期表头跨行合并展开后，表头文字会落到表头下方的行里，被当成课程（如把「星期一」「调课信息」解析成课）。已排除纯星期标签与整行合并的说明行。
22. **PDF 里的地点行被并入下一门课**：地点常单独占一行且不像「节次行」，按节次行切分时会被下一门课吸走，表现为「课程名变成教室名、地点为空」。已改为节次行后按「地点/单双周标记」判据回吸，并做折行名称的复原。
23. **引导卡片在小窗口下溢出视口（新手指引）**：引导卡片按「目标下方优先」定位，当目标（课表面板）很高、上下空间都不足时，卡片会被压到 200px 甚至顶出屏幕。已改为「下方 → 上方 → 贴底居中」三级降级，并按可用空间给出 `maxHeight`（超出可滚动），实测卡片完整可见（`top=454 / bottom=834`，视口高 846）。
24. **靠 `transform` 居中失效（新手指引）**：卡片用 `left:50% + transform: translateX(-50%)` 居中，但入场动画 `animate-in-up` 的 `animation-fill-mode: both` 会写入 `transform: translateY(0)`，把 inline 的 `translateX` 覆盖掉，卡片实际偏右约 120px。已改为 `left/right: 0 + margin: auto` 水平居中、flex 容器垂直居中，不再依赖 transform。
25. **聊天页在未配置 AI 时没有引导要讲的那个按钮（新手指引）**：引导第 6 步要讲聊天页顶部的「我的日程」开关，但新用户此时还没配置 AI，聊天页显示的是配置引导，开关根本不存在——引导会退化成居中卡片（不会报错）。已调整该步文案，明确说明「配好 AI 后才会出现该开关」，避免图文不符。

|---|---|

## 16. 把软件分享给别人用

### 15.1 一句话原则

**分享的是软件，不是你的 API Key。** 别人要用，就得填他们自己的 Key——这既是 BYOK 的设计，也是必须守住的安全边界：`nvapi-` 这类 Key 谁拿到谁就能花掉你的额度。

### 15.2 生成安全的分发包

```bash
npm run pack:share
```

它会复制项目到 `share/zhixu-workbench/`，并自动：

- 排除 `node_modules`、构建产物、`.git`；
- **排除 `.local/`**（含明文密钥的那份配置）；
- 全量扫描输出目录，**一旦发现疑似密钥（`nvapi-…` / `sk-…`）就中止打包**并提示。

把生成的目录压缩后发给对方即可（`share/` 已在 `.gitignore` 中）。

### 15.3 对方怎么用

```bash
npm install
npm run dev          # 打开 http://localhost:5173
```

然后到「AI 配置」添加自己的 Key（如果对方愿意，也可以照 5.1 用 `.local/ai-config.json` 免配置）。

**数据是完全隔离的**：每个人的导航数据、AI 配置、聊天记录都存在各自浏览器的 IndexedDB 里，互不可见；本机后端也不落地任何聊天内容。

### 15.4 别人怎么拿到自己的 API Key（以 NVIDIA NIM 为例）

- 打开 <https://build.nvidia.com> 注册 NVIDIA 开发者账号（**免费，不需要信用卡**）；
- 在任意模型页点「Get API Key」即可获得 `nvapi-` 开头的 Key，**注册即送 1,000 credits**，还可申请追加（合计上限约 5,000）；速率约 40 RPM；
- 免费层适用于**开发、测试、研究**；若要用于生产（真实终端用户/商业用途），需 NVIDIA AI Enterprise 授权；
- 其它服务商同理（DeepSeek、硅基流动、智谱、OpenRouter 等），本应用已内置预设，填 Key 即可。

### 15.5 如果 Key 已经泄漏

只要 `.local/ai-config.json` 被发出过（或提交进过 Git、截图里露过），就应当视为已泄漏：

1. 立刻去服务商控制台**吊销旧 Key 并重新生成**；
2. 更新本地 `.local/ai-config.json`；
3. 确认 `.local/` 未被提交：`git status --ignored` 查看。

### 15.6 想做成「双击即用」的桌面版？

当前是**源码分发**，需要对方装 Node.js。如果希望非技术用户也能直接用，可以再包一层桌面外壳（Tauri / Electron）产出安装包——**这一版尚未实现**，需要的话可以继续加。

## 17. 部署到静态网站（无本地后端模式）

本应用默认需要一个本地 Node 代理后端（8787）来转发 AI 与天气请求。但如果你只想把**前端静态托管**到任意静态空间（CloudStudio、GitHub Pages、Vercel、Netlify 等），可以用「直连模式」构建：AI 与天气改为由浏览器**直接**请求你配置的服务商 / 公开数据源（Open-Meteo、BigDataCloud 都支持浏览器跨域），无需任何后端。

```bash
# 构建「直连模式」静态产物到 dist-web/
npm run build:web
# 然后将 dist-web/ 整个目录上传 / 部署到你的静态托管空间
```

要点：

- **BYOK 不变**：API Key 本就只存在于用户浏览器，直连模式只是把请求从「经本机代理」改为「浏览器直接发往服务商」，密钥不会流向任何第三方。
- **AI 直连前提**：你配置的服务商需支持浏览器跨域（CORS）。NVIDIA NIM、OpenAI、OpenRouter、硅基流动、Together 等主流服务均支持；个别服务（或国内网络访问境外）若不支持 CORS，仍须走本地代理（`npm run dev` / `npm start`）。
- **天气直连**：Open-Meteo 与 BigDataCloud 均为浏览器可直接调用的免密钥数据源，定位坐标照会发送给它们（与本地模式一致，已在界面说明）。
- **导航 / 课表 / 日程** 全部是浏览器端能力（IndexedDB），直连模式下完全可用、且与后端无关。
- 构建产物用的是相对路径（`base: './'`），挂在子路径下也能正常加载。

> 部署到静态空间后，应用首屏会尝试拉取 `/api/bootstrap`（本地引导配置）；该接口不存在时**自动跳过**，不影响使用——用户首次打开是一个空的、等待自己配置的工作台。

### 17.1 部署到 GitHub Pages（地址固定不变）

本项目已按 GitHub Pages 配好，仓库的 `gh-pages` 分支即线上站点，Pages 的 Source 选该分支即可，**地址永久固定**：

```
https://<用户名>.github.io/<仓库名>/     # 本项目：https://qiruixu.github.io/zhixu-workbench/
```

更新流程（每次改完代码重新发布一次该分支即可，地址不变）：

```bash
# 1) 用子路径 base 构建（base 必须与仓库名一致）
npx vite build --base=/zhixu-workbench/ --outDir dist-pages

# 2) 补两个静态托管必需的小文件
cp dist-pages/index.html dist-pages/404.html   # SPA 深链接兜底（BrowserRouter 需要）
touch dist-pages/.nojekyll                     # 跳过 Jekyll 处理

# 3) 把 dist-pages/ 的内容发布到 gh-pages 分支
```

> ⚠️ **两个容易踩的坑**（本项目已处理）：
> 1. **路由 basename**：`src/main.tsx` 里 `BrowserRouter` 的 `basename` 跟随 `import.meta.env.BASE_URL`。子路径部署必须设置 base，否则路由会被 `*` 兜底重定向回根目录，表现为白屏或跳转错误。
> 2. **深链接 404**：静态托管没有服务端回退，直接访问 `/chat`、`/ai` 会 404，需要 `404.html` 兜底（内容与 `index.html` 相同）。
>
> 另外：`github.io` 域名在**部分国内网络**下无法访问，如需给国内用户使用，建议同时部署到国内可访问的静态托管（如 CloudStudio、腾讯云 COS、Vercel 自定义域名等）。
